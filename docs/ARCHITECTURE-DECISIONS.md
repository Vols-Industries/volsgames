# Architecture decisions

| # | Decision | Rationale |
|---|---|---|
| 1 | Rust for the whole stack | No GC on the hot path, layout control, quinn/wasmtime/tokio ecosystem |
| 2 | QUIC first: WebTransport for browsers, raw QUIC for native, WebSocket fallback | TCP head-of-line blocking is incompatible with the latency goal |
| 3 | Own reliability layer on datagrams, not QUIC streams, for game state | Per-channel semantics (reliable-ordered, unreliable-sequenced) and ack bitfields |
| 4 | Routing by room: one room always lives in one process; no pub/sub on the hot path | Fan-out through a broker is O(servers x clients) and adds a hop |
| 5 | Room = single-threaded actor pinned to a core, fixed tick, zero allocation per tick | Predictable tail latency |
| 6 | Customer logic = WebAssembly room modules in wasmtime with fuel and epoch limits | Any language, sandboxed, metered, deterministic, no network hop |
| 7 | Deterministic rooms with an event log | Replay, cheat review, reconnect by replay |
| 8 | Reconnect with state recovery is a day-one feature | First thing a mobile game hits |
| 9 | Benchmarks are a first-class deliverable, regenerated by CI | Latency is proven, not claimed |
| 10 | Open core, Apache-2.0: core, protocol, SDKs, examples and load generator public; hosted control plane private | Self-host path for users |

Pending (tracked as issues): gateway and room host as one binary for v1; WIT component model vs core Wasm for the host ABI.

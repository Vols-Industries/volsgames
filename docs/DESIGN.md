# Platform design (draft 0)

## Components

### Edge gateway
- Terminates client transport: QUIC via WebTransport for browsers, raw QUIC for native clients,
  WebSocket as fallback for networks that block UDP.
- Authenticates a session token issued by the control plane, then forwards to the room host that
  owns the room. Players in one room always land on one process.
- Rust: tokio + quinn (+ h3/webtransport), tokio-tungstenite for the fallback.

### Room host (the only latency-critical process)
- One process hosts many rooms. Each room is a single-threaded actor pinned to a core:
  single writer, no locks on the hot path.
- Fixed-tick authoritative loop per room. Tick rate is per-game config.
- One wasmtime instance per room running the tenant's module, with fuel/epoch limits.
- Channels: reliable-ordered (lobby, chat, turns), unreliable-sequenced (state). Snapshot
  interpolation and delta compression against last-acked state for real-time games.
- Zero-allocation hot path: pooled buffers, flat serialization (rkyv or hand-rolled), no
  per-message heap objects.
- Host ABI exposed to Wasm: read room state, broadcast, send to one player, kick, set timer,
  key-value get/put (room-scoped), emit webhook event, log, metrics.

### Control plane (latency does not matter)
- Tenants, games, API keys, module upload and versioning.
- Matchmaking and room placement: hands the client a gateway address plus a signed session token.
- Fleet management: which room hosts exist, capacity, draining. Agones on Kubernetes or a small
  custom manager; decide later.
- Billing meters: player-minutes, messages, bytes, Wasm fuel.
- REST API for tier 3 and the dashboard. Webhooks out.
- Rust for one toolchain (Go would be fine too).

### Client SDKs
- The customer experiences the product through the SDK, not the server. More work than the
  server and the main reason people pick an incumbent.
- Order TBD (see OPEN-QUESTIONS): JavaScript (browser, forces the WebTransport path, zero-install
  demo) vs Unity C#. Unreal and Godot later.

## Security from day one
- Session tokens signed by the control plane, short-lived, bound to tenant+game+room.
- Per-client rate limits, replay-safe sequence numbers, encrypted payloads (QUIC gives this).
- Per-tenant quotas: rooms, players, bandwidth, fuel. Noisy neighbour is the whole game in
  multi-tenant real-time.
- Logging: every action logged with opaque ids, never payload contents, never secrets.
